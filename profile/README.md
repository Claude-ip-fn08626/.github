<h2>一、先按特征对号入座</h2>
<p>判断属于哪个场景，看的不是账号注册了多久，而是这个号现在处在什么阶段、承担什么任务。同样是三个月前注册的号，一个天天在跑对话，一个躺了两周没登录，适配方式完全不同。</p>
<h3>三种识别信号</h3>
<p>信号一，最近一次登录距今多久。超过七天未登录，再登录时环境必须与上次完全一致，不能顺手换个出口。信号二，这个号有没有绑定支付。绑了支付的号，出口变更的成本远高于未绑定的。信号三，这个号是否已形成稳定行为画像，看它过去三十天的登录城市是否只有一个。</p>
<h3>静态与动态的分界线</h3>
<p>静态住宅 IP 适合「环境必须固定」的场景：注册、订阅扣费、长期挂机、身份验证。动态住宅适合「只要求地区正确」的场景：批量抓取、临时验证、一次性查询。分界线是动作对「一致性」的敏感度，而不是动作本身看起来敏不敏感。</p>

<h2>二、场景一：老号日常登录与对话</h2>
<p>老号的适配原则只有一条：不动。它已经形成了稳定画像，任何看起来无害的改动都可能成为变化的起点。</p>
<h3>配置要点</h3>
<p>出口锁定一条静态独享线路，不配自动切换。备用线可以买，但设置为手动接管，不自动切。设备与浏览器配置目录固定，不因为换电脑就换环境。时区、语言、字体跟随出口，不做额外调整。</p>
<h3>什么时候才动它</h3>
<p>只有三种情况才调整老号：出口线路物理不可用、归属库记录发生变更、账号已被明确限制必须重建。除此之外的「感觉有点慢」「想试试别的地区」都不构成理由。改动的成本不是当下那一次，而是之后每次登录都要重新建立一致性。</p>
<h2>三、场景二：新号注册期</h2>
<p>注册期是三十天窗口，这三十天的环境会成为账号的初始画像。这段时间的配置要一次做对，后面尽量不改。</p>
<h3>注册当天的配置</h3>
<p>指定地区的一条静态独享线，注册全程不变。环境三件套对齐，注册前预热十分钟。表单间隔 20 到 40 秒，不要连续秒过。整个流程控制在十五分钟内完成，中途不做其他操作。</p>
<h3>注册后的前三十天</h3>
<p>这三十天尽量用同一出口、同一设备、同一时段登录。每天操作次数不必多，但要稳定，比如每天同一时段登录一次、跑几轮对话。稳定的节奏比高频操作更能建立画像，也不容易踩到频率阈值。</p>

<h2>四、场景三：风控后的重建</h2>
<p>重建最容易做错的地方是「复用」。用旧的浏览器配置、旧的出口段、旧的操作脚本重开一个号，等于把旧画像原封不动搬过去，通常撑不过第一周。</p>
<h3>必须重新来过的四项</h3>
<p>出口要换到不同 /24 段，最好不同 ASN；浏览器配置目录要新建；设备标识要重置；操作节奏要调整，不必刻意不同，但不要和前一个号完全同步。四项里最容易被忽略的是第四项，两个号的登录时间完全一致，本身就是关联信号。</p>
<h3>重建期不要急着上量</h3>
<p>新开的前两周只做轻量操作，登录、浏览、少量对话。第三周开始逐步增加，第四周再考虑绑支付。急着上量会把重建期压缩成一次集中测试，失败率明显更高。</p>
<h2>五、场景四与场景五：协作与跨地区</h2>
<p>这两个场景的共同点是「一条线不够用」，区别在于是按人分还是按地区分。</p>
<h3>多人协作：一人一线</h3>
<p>两个人登录同一批号时，出口必须按人分，不能按号分。同一个人昨天用这条线、今天用另一条，比两个人共用一条线更容易被识别。台账里记「谁用哪条线」，交接时连人带线一起交接。</p>
<h3>跨地区：按市场配线</h3>
<p>要开新地区市场，先把该地区的线路跑通再动账号。每个市场配一组静态独享线，不与已有市场混用。切换市场时新建环境，不要在旧环境里改地区参数，改参数等于在一个已有画像上叠加矛盾信息。</p>

<h2>六、常见问答</h2>
<h3>老号换了新电脑，要不要换出口？</h3>
<p>答：不要。换设备已经是变化，再换出口就是两个变化叠加。正确做法是新电脑上把环境配置成与原来一致，出口保持不变，登录后观察一段时间再说。</p>
<h3>静态线能不能给同一个人手上的多个号用？</h3>
<p>答：不建议。多个号共用一条出口，等于把这些号绑在同一个地址上，一个出问题其他都会被牵连。要省成本可以压缩账号数量，不要压缩线路数量。</p>
<h3>风控后多久能重开？</h3>
<p>答：没有统一答案，取决于被限制的原因。保守做法是先查清原因，换线换环境后先跑轻量操作两周，观察是否稳定，再逐步恢复。急着重开通常要多试几次。</p>
<h3>跨地区切换时原来的号怎么办？</h3>
<p>答：原来的号留在原地区，不要跟着搬。新市场用新号新线，两套并行运行。把老号迁到新地区，会同时改动出口、时区、语言三项，风险远高于新开一个号。</p>
<h2>合规提示</h2>
<p>场景配置仅适用于自有账号与已获授权的业务环境，不得用于绕过平台规则、伪造身份信息或批量注册。</p>
<p>多人协作时应明确账号与线路的使用权限，操作日志限定在必要范围内留存，涉及个人信息的字段需脱敏处理。</p>
